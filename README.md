# FieldOps

A data app with a Python backend and a thin React frontend, built so that most of the work stays in Python.

| Part | Stack |
| --- | --- |
| `backend/` | FastAPI, uv, Plotly + pandas for charts, raw SQL written in **SAP HANA dialect** (running on SQLite for now) |
| `frontend/` | Vite, React, TypeScript, Tailwind + shadcn/ui, TanStack Query, TanStack Router, AG Grid Community, Plotly.js, assistant-ui |

## Running locally

```sh
# Terminal 1: API on http://127.0.0.1:8000 (interactive docs at /docs)
cd backend
uv sync
uv run fastapi dev app/main.py

# Terminal 2: UI on http://localhost:5173 (forwards /api to the backend)
cd frontend
npm install
npm run dev
```

## How it fits together

```
Browser (React)                       FastAPI (Python)
───────────────                       ────────────────
routes/items.tsx ── useQuery ──────►  items/router.py ──► items/service.py ──► HANA SQL ──► DB
  <DataGrid>      (generated client)                  └─► items/charts.py  (Plotly figure)
  <PlotlyChart>  ◄── figure JSON ─────────────────────────┘
```

- **The backend owns logic, SQL, and charts.** Build charts with `plotly.express` just like in Streamlit and return them with `figure_response(fig)`.
- **The frontend displays data.** `<DataGrid>` (AG Grid) shows tables and `<PlotlyChart>` shows backend figures.
- **The API client is generated.** `npm run gen:api` reads FastAPI's OpenAPI schema and writes typed functions to `frontend/src/api/generated/`. If a backend change breaks the frontend, `npm run build` reports it.
- **Service functions are the source of truth.** The REST endpoints call them, and future assistant/agent tools will call the same functions.

See [CLAUDE.md](CLAUDE.md) for the step-by-step recipe for adding a feature.

## Assistant

The header's "Assistant" button opens a chat panel backed by an OpenAI model. To enable it, create `backend/.env` with:

```sh
OPENAI_API_KEY=sk-...
OPENAI_MODEL=gpt-4o-mini   # any model your account can use
```

Then restart the API. Without a key the panel still opens and tells you what to set. The key stays on the
backend, and requests stream through `POST /api/assistant/chat`. Edit the assistant's instructions in
`backend/app/assistant/prompts.py`.

## HANA SQL on SQLite

Write all SQL for HANA. The SQLite adapter (`backend/app/db/sqlite.py`) translates the HANA-only syntax it knows about:
`CREATE COLUMN TABLE`, `... GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, `CURRENT_UTCTIMESTAMP`/`CURRENT_UTCDATE`, and the `DUMMY` table.
If HANA SQL you write fails on SQLite, add a rule to `_TRANSLATIONS` there. Always use `?` parameters.

To switch to HANA: `uv sync --extra hana`, then set `DB_BACKEND=hana` and the `HANA_*` values in `backend/.env` (see `.env.example`).
The HANA adapter has not been tested against a real HANA instance yet.
